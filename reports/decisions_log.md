# Decisions log

Every deviation from the project documents (01–06) is recorded here: what, why, effect.

| ID | Date | What | Why | Effect |
|---|---|---|---|---|
| D-001 | 2026-10-31 | The raw CSV isn't copied or linked into `data/raw/`. Its location is set in a new back-end-only `paths:` block in `config/config.yaml` (`paths.raw_csv`). | The working filesystem doesn't support symlinks, and copying 64 MB into the deliverable folder is wasteful. | The raw file is still never edited. The contract part of `config.yaml` is verbatim from 04 §2. The front end ignores `paths`. To run elsewhere, set `paths.raw_csv` or drop the CSV into `data/raw/`. |
| D-002 | 2026-10-31 | Contract format: **JSON Schema draft 2020-12** (`contract/schema.json`), not Pydantic. | 04 §8 says pick one. JSON Schema is language-neutral and needs no model code. | Cross-field rules (monotonicity, `observed_at_utc ≤ now_utc`, flight probabilities equal to hour risk, lead-time consistency) are asserted in the tests, not the schema. |
| D-003 | 2026-10-31 | The six examples are generated by `contract/make_examples.py` with illustrative numbers. Refusal messages for LEAD_TOO_LONG and UNKNOWN_AIRPORT were drafted by the back end, since 04 §5.2 only gives the LEAD_TOO_SHORT text. | Guarantees the "flights equal hour risk" rule holds by construction. | **Needs front-end review and sign-off** (Checkpoint 0 says the examples are written together). |
| D-004 | 2026-10-31 | `streamlit` isn't pinned in `requirements.txt`. | It isn't installed in the back-end environment. | The front end pins it when B1 starts. |
| D-005 | 2026-10-31 | In the schema, `request` fields may be `null` on refused/error responses. `confidence.reasons` needs at least 1 item. `obs_age_h` is an integer from 0 to 12. | Unparseable input still has to return a valid refusal or error. The 0–12 range follows the NO_RECENT_WEATHER rule. | Stricter checks on `ok` responses only. |
| D-006 | 2026-10-31 | The "3 decimals" rule for probabilities is checked in the tests, not with JSON Schema `multipleOf: 0.001`. | `multipleOf` wrongly rejects valid floats such as 0.702 because of floating-point rounding. | Same rule, enforced reliably. |
| D-007 | 2026-10-31 | Added `config/airport_timezones.yaml` (IANA time zone for all 350 airport codes in the file), built from each airport's state plus known exceptions (e.g. PNS/VPS/ECP Central, ELP Mountain, TYS/CHA/TRI Eastern). Added check **V3b**. | 02 A1.2 says arrival time must be departure UTC + scheduled duration. That needs the *origin* time zone of every flight into ATL/DFW, not only the two hubs in `config.yaml`. 02 §0 allows reference settings such as time zones. | V3b checks the table against the file: implied local arrival equals `CRS_ARR_TIME` for 100.00% of flights (99.99% for flights touching ATL/DFW). Kept as a separate file so the contract part of `config.yaml` stays verbatim. |
| D-008 | 2026-10-31 | `wpgt` **dropped**. | After zeros become null, only 2.36% of airport-hours have a value, below the 10% rule in 02 A1.3. | No gust feature. Wind is represented by `wspd_kmh` only. |
| D-009 | 2026-10-31 | When readings for the same airport-hour are combined, `coco` takes the **most frequent** value (ties go to the lower code), not the median. Numeric columns use the median, as instructed. | The median of a categorical code is meaningless (it could produce a code that nobody observed). | Only affects the 26 conflicting airport-hours. |
| D-010 | 2026-10-31 | Range check for `wpgt` set to 0–300 km/h (02 gives none). | D-011 | 2026-10-31 | Added `backend/common.py` (config/paths helper) and `backend/validate.py` (V1–V10 + figures), which aren't in the 02 layout. | Keeps `run_all.py` short and puts the checks in one module. | Layout otherwise unchanged. |

## Lead decisions at merge (cp0-contract)
| ID | Decision | Why |
|---|---|---|
| L-001 | One repo. The front end's `contract/schema.json` and `contract/examples/*.json` are **authoritative**. The back end's copies are retired. | Two diverging contracts existed. The back-end GREEN example had `triggered_by: null`, which the front-end schema rejects, so every real GREEN answer would have shown the error card. |
| L-002 | `triggered_by` is always a string | Traceability: every recommendation names its rule |
| L-003 | `paths.raw_csv` is now relative (`data/raw/...`) | The absolute `/mnt/session/...` path breaks on every other machine |
| L-004 | One `requirements.txt` (back-end pins + `streamlit==1.66.1`) | One environment for the fresh-clone test |
| L-005 | `contract/make_examples.py` is kept but must not overwrite the canonical examples without a joint pull request | Front-end tests depend on the exact example values |
| L-006 | Test files renamed: `test_contract_backend.py`, `test_contract_frontend.py` | Name clash on merge |
